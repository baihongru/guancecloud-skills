# Span 证据指南

本文定义如何把 span 现象转成可求证的 RCA 线索。不要只因为某个 span 慢就直接写根因；慢只是入口，根因需要证据链闭环。

## 异常语义

### 显性错误

信号：

- `status != ok`
- `error_type`、`error_message`、错误堆栈存在
- 关键词：timeout、cancel、refused、reset、unavailable、deadline、retry

求证：

- 查同一时间窗内同服务、同 resource、同依赖实例的错误数量趋势。
- 查日志或错误聚类，确认错误是否集中在同一异常类型。
- 查事件，确认是否有发布、重启、配置变更。

结论：

- 只有错误趋势和慢请求趋势同时匹配，才能说错误是耗时异常的重要原因。
- 如果错误很少，只能作为慢请求伴随现象。

### 性能异常但状态正常

信号：

- `status=ok`，但 `duration` 明显高于基线或同类 span。
- p99/max 异常，而 avg 或 p75 不明显。
- 下游 Redis/DB/HTTP/RPC span 的耗时解释了父级耗时。

求证：

- 对同一 `resource` 或依赖实例做趋势查询。
- 比较异常窗口和前置基线窗口。
- 查依赖指标、慢查询、连接数、CPU、内存、网络或服务端日志。

结论：

- 这是尾部性能问题的常见形态，不应因为 `status=ok` 忽略。

### 父子耗时贡献异常

信号：

- 某个 child span 占 parent span 大部分耗时。
- 多条慢 trace 都指向同一个 child span 模式。
- child span 开始时间和父级慢点对齐。

求证：

- 拉取完整 trace 子 span。
- 计算慢 child span 的服务、resource、实例字段是否重复出现。
- 聚合该 child span 对应资源在异常窗口的趋势。

结论：

- 如果同一 child span 模式在多条慢样本中重复出现，它就是优先调查方向。

### 单资源或单实例趋势上涨

信号：

- 整体异常由某个 `resource`、`db_host`、endpoint 或 `base_service` 主导。
- 该维度在异常窗口内 p99/max 上涨。
- 请求量未明显上涨但耗时上涨。

求证：

- 同维度查询前置基线和异常窗口。
- 查该资源是否有发布、配置变更或依赖端指标异常。

结论：

- 单点资源或实例上涨通常比全局趋势更接近根因。

## 跨域证据选择

- 慢 Redis/DB：查依赖服务指标、慢查询、连接池、CPU、内存、网络；必要时查调用方是否新增高成本命令。
- 慢 HTTP/RPC：查下游服务自身入口耗时、错误率、发布事件和基础设施。
- 慢 `local` span：查 profiling、应用日志、线程池、锁等待、GC。
- 单 pod/host：查容器重启、CPU throttling、内存、磁盘、网络、节点事件。
- 单版本：查发布事件、版本对比、回滚或灰度范围。

## 结论分级

- `已确认`：整体趋势、候选服务/接口、慢 span 模式、跨域证据一致。
- `疑似`：trace/span 证据强，但缺少跨域证据。
- `待验证`：只有聚合趋势或单条样本，尚未形成重复证据。
- `无法判断`：数据过稀疏、噪声过多、查询失败或字段缺失。

## 中断条件

遇到以下情况应停止自动下钻：

- 异常窗口过多，无法判断关注点。
- 异常点比例过高，整体波动像噪声而不是明确事件。
- 数据点过少或时间间隔过稀疏。
- 关键字段缺失，无法还原 trace 或识别依赖。

中断时输出趋势图、异常段列表和缺失证据，请用户指定关注时间段或补充上下文。
